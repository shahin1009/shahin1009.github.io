Language Models in Robotics

Combining LLM-based decision making with physical robotic actions for intelligent task execution.

Introduction

Large language models (LLM) encode a wealth of semantic knowledge about the world that could be extremely valuable for robots executing high-level, temporally extended instructions expressed in natural language. Therefore the question may arise: is it possible to use LLMs to make robotic tasks more intelligent? This project presents a method for combining LLM-based decision making with physical robotic actions to perform tasks that need an intelligent approach. Using chess as our domain, we demonstrate how low-level pick-and-place actions can be integrated with language models to enable a robotic arm to play chess following requested strategies, such as specific standard openings.

Method

The pipeline operates with the LLM playing as one of the players (for example, white pieces), provided with instructions to generate proper and standard moves (for example, opening the game with the London system). Additionally, it is required to provide the command in a specific framework. The command is then parsed and checked for the legality of the move, the correction of the command, and other checks; in the case of a wrong command, a feedback message is fed back to the LLM Decision maker to try again.

On the other side, the pipeline continues by interpreting human queries, generating candidate actions through an LLM, filtering these actions based on both semantic intent and game legality, and executing validated commands using a robotic arm in a simulated or real chess environment. The downstream components handle the integration architecture, where the filtered and validated commands converge at the action output text, representing the finalized textual representation of the selected action. Special cases such as board resets are also handled at this stage. This output branches into two key processing modules: a Cliport module that grounds the instruction into visual and physical features, and a Mapping module that converts the board-level move into robot-reachable 3D coordinates. The outputs from both modules are fused into low-level motion instructions, which are ultimately sent to the robotic controller for execution. The feedback loop from the legality check back to the LLM allows for iterative refinement in case of ambiguous or invalid actions, enhancing the robustness of the system.

Chess and the Decision Maker LLM

Chess is not merely a game of tactics and rules but also one of long-term strategy and structured decision-making. A critical phase of the game is the opening, aimed at developing pieces efficiently, controlling the center, ensuring king safety, and preparing for the middlegame. In this project, we focus on guiding a robotic agent to execute structured openings by interpreting natural language prompts and integrating language model strategies with physically legal moves on a chessboard. While LLMs demonstrate impressive generalization and reasoning capabilities, they are not specialized chess engines and can occasionally produce illegal or illogical moves. These limitations necessitate the use of auxiliary systems to filter or correct model outputs and maintain the validity and integrity of gameplay.

To guide the LLM to make proper decisions and avoid illegal or illogical moves, the python-chess library is utilized. Using python-chess, we construct a carefully engineered prompt for each move. This prompt includes the full board state in FEN format and the move history, alongside a structured list of legal moves grouped by piece. It also incorporates contextual strategy guidance and provides feedback on any previous failed move attempts, supplemented by a visual description of the board to aid spatial understanding.

The LLM is instructed to respond in a strict textual format. These outputs undergo rigorous validation, involving regular expression pattern matching to ensure syntactic correctness and verification that piece names and target squares are valid identifiers. Finally, the system checks that the move strictly conforms to chess rules in the current board state. Valid commands are forwarded to robot control, while malformed or illegal commands trigger a new prompt with failure feedback.

SayCan LLM and Affordance Scoring

An alternative and complementary approach to direct command generation involves a multi-stage scoring mechanism to select the most appropriate action from a predefined set of possibilities. This method leverages both the LLM’s understanding of natural language intent and rigorous physical and rule-based validation. The affordance scoring module acts as a critical validation layer, evaluating whether a candidate action is permissible according to the rules of chess and the current physical state of the game board as represented in the PyBullet simulation.

The core functionality processes a list of candidate actions expressed in string format, parsing them to extract the specific piece intended to be moved and its proposed destination square. The system determines the color of the piece and verifies the current state of the simulation by checking whether the named piece exists within the PyBullet environment. Its actual physical position on the board is determined by comparing its 3D coordinates from the simulation with a pre-mapped set of coordinates. The system then creates a temporary copy of the current board state, isolates the validation, and checks the legality of the move using the python-chess library. If all checks succeed, the system assigns the action an affordance score of 1; if any part of the validation fails, the action is given a score of 0.

Combined Scoring and Final Action Selection

To assess the alignment between potential actions and the user's command, the system uses the LLM to evaluate how well each predefined action fits as a response to the user’s input query. The system extracts log probabilities for each token the model produces and normalizes these raw scores to a [0, 1] range. The final decision on which action to execute is made by integrating the LLM interpretation of the user's intent with the physical and rule-based validity check.

$$ \text{Combined Score} = \text{Normalized LLM Score} \times \text{Affordance Score} $$

This scoring mechanism guarantees that any action deemed invalid by the affordance check is automatically excluded from consideration, regardless of how strongly the LLM favored it. The system selects the action with the highest positive combined score for execution. This structured sequence demonstrates the system's capacity to interpret varied user instructions, validate them against game rules and physical state, and select appropriate robotic actions.

LLM and Robotics Arm Integration

To bridge the gap between natural language high-level actions and robotic execution, the structured text command requires translation. The translation process begins by splitting the command at the keyword "and" to extract the pick and place targets. The system then identifies known objects or locations from pre-registered dictionaries, retrieves the specific 3D coordinates for the identified entities, and generates an action dictionary containing pick and place keys with their associated position vectors. This design restricts vocabulary to valid, environment-specific terms, ensuring actions correspond directly to tangible entities in the workspace.

CLIPORT Implementation

Another effective approach for command to action translation is CLIPORT. This model is designed to interpret natural language instructions alongside visual input from a camera to perform robotic manipulation tasks. To improve spatial understanding, the visual input is augmented with coordinate channels, providing the model with explicit positional context alongside visual and textual cues. The successful operation of Cliport relies on pre-trained models, utilizing a pre-trained CLIP model to encode textual instructions and a TransporterNets architecture initialized with pre-trained weights for the manipulation logic.

To train Cliport for the specific task of moving chess pieces, a dataset of demonstrations was generated using a scripted policy. The simulation environment is reset with a configuration of chess pieces, and for each action, a top-down camera image is captured and resized to 224 by 224 pixels. The 3D pick and place coordinates from the scripted policy are then converted to 2D pixel coordinates, and each sample is accumulated and saved into a single pickle file targeting an 8,000 sample size.

Results and Conclusion

The simulation environment is created using PyBullet, a physics engine that provides precise collision detection and dynamics simulation. The robotic system consists of two main components: a Universal Robots UR5e 6-degree-of-freedom robotic arm and a Robotiq 2F85 Gripper attached to the end-effector. Two camera views—a perspective side-view camera and an orthographic top-view camera—are configured for observation and visual feedback.

Environment configuration showing the UR5e Arm and chessboard.

The robotic arm performs pick-and-place operations using a strictly defined motion sequence. It begins by hovering over the source position before moving down to grasp the piece. After returning to the hover height, it navigates to the target position, lowers until contact is detected, releases the gripper, and safely returns to its home position.

The results indicated that the LLM could successfully follow strategic instructions for specific chess openings, such as the Giuoco Piano, London System, and Nimzowitsch Defense. However, its performance tended to be less consistent as the game progressed into more complex middlegame and endgame scenarios, largely because the LLM is not a specialized chess engine.

Overall, experiments with CLIPORT successfully executed the task of positioning a limited set of visually distinct chess pieces on the board after being trained on the dataset. This project demonstrated the promising potential of LLMs to enhance robotic intelligence and facilitate more natural human-robot interaction, while also highlighting current limitations when dealing with highly complex, specialized domains like chess.
